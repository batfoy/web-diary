MASTER BLUEPRINT: Personal Diary App (Vanilla JS → React Native Migration)
1. Общее описание проекта
Это оффлайн-первичное (offline-first) приложение для ведения личного дневника. Оно вдохновлено UX-паттернами приложений My Diary и Journey. Ключевые особенности: мгновенное автосохранение, поддержка Rich Text (включая кастомные эмодзи-картинки прямо в тексте), мощная система фильтрации/сортировки и строгая защита данных (PIN-код).
Цель миграции: Перенести текущую функциональность на React Native для публикации в Google Play и App Store (iOS), сохранив при этом ощущение нативного, быстрого и надежного приложения.
2. Жесткие правила UX и Бизнес-логики (Не менять при миграции!)
Нет понятия "Черновик" в интерфейсе. Как только пользователь вводит первый символ, запись создается в базе данных. Любое закрытие приложения, свайп назад или клик вне поля ввода автоматически сохраняет текущее состояние. Потеря данных недопустима.
Неизменяемая дата публикации. При редактировании старой записи поле date (дата создания) не меняется. Меняются только updatedAt и editedAt. В интерфейсе это отображается как: 28 октября 2026 · изм. сегодня.
Панель инструментов (Toolbar): Находится внизу экрана, над клавиатурой. Имеет горизонтальный скролл. При нажатии на инструмент (например, "Эмодзи"), панель не открывает новое модальное окно на весь экран. Вместо этого над основной панелью плавно выезжает подпанель с инструментами. Она закрывается по клику на галочку (✓), по повторному клику на иконку инструмента или по клику в поле ввода текста.
Сортировка по умолчанию: По дате создания (новые сверху). Редактирование записи не поднимает её вверх, если не выбрана сортировка "По дате изменения".
3. Модель данных (Data Schema)
Каждая запись в базе данных (сейчас IndexedDB, в будущем SQLite/WatermelonDB) должна строго соответствовать этой структуре:
json
{
  "id": "1698765432100",          // string, timestamp создания
  "date": "2026-10-28T12:00:00.000Z", // string, ISO дата публикации (НЕ МЕНЯЕТСЯ при редактировании)
  "createdAt": 1698765432100,     // number, timestamp
  "updatedAt": 1698765432100,     // number, timestamp последнего сохранения
  "editedAt": 1698765432100,      // number | null, timestamp редактирования (для лейбла "изм.")
  "title": "Мой заголовок",       // string
  "content": "Текст с <img class='inline-emoji' src='...' />", // string, HTML-формат для поддержки inline-картинок
  "mood": "😊",                   // string, эмодзи настроения
  "wordCount": 42,                // number, количество слов (игнорируя HTML-теги)
  "tags": ["#работа", "#идеи"]    // array of strings, всегда в нижнем регистре
}
4. Текущий функционал (Feature Checklist v2.x)
При миграции все эти функции должны быть воспроизведены:
Записи: Создание, чтение, обновление, удаление (CRUD). Rich Text ввод.
Тулбар: Шаблоны, Фон (заглушка), Эмодзи (стандартные + кастомные PNG), Теги (#), Текст (заглушка), Списки (заглушка), Таблицы (заглушка).
Кастомные эмодзи: Поддержка вставки картинок (PNG) прямо в строку текста как inline-элементы.
Навигация и Фильтры: Боковое меню (гамбургер), Поиск по тексту/заголовку, Фильтр по дате (из календаря), Фильтр по тегам, Фильтр по настроению.
Сортировка: По дате создания, по дате изменения.
Визуализация: Календарь (с эмодзи настроений на днях), График настроений (Canvas/Chart), Статистика (всего записей, слов, дней активности, самое частое настроение).
Безопасность: Установка, ввод и сброс 4-значного PIN-кода при запуске.
Данные: Экспорт в JSON (для бэкапа) и Markdown (для чтения). Импорт из JSON (с дедупликацией по ID).
Темы: Светлая, Тёмная, Пастельная (CSS-переменные).
5. Архитектура React Native (Рекомендации для миграции)
Когда мы начнем разработку на React Native, используй следующий стек:
Фреймворк: Expo (с Dev Client для кастомных нативных модулей). Это упростит сборку под iOS и Android и публикацию в сторы.
База данных: WatermelonDB или expo-sqlite.
Почему: WatermelonDB идеально подходит для offline-first приложений, реактивна и быстро работает с большими объемами текста, в отличие от AsyncStorage.
Rich Text Редактор: Это самый сложный элемент.
Вариант А: Использовать библиотеку react-native-pell-rich-editor.
Вариант Б: Написать кастомный компонент, который парсит HTML-строку из content и рендерит её через комбинацию <Text> и <Image> (с inline позиционированием для эмодзи).
Управление состоянием: Zustand (легкий, быстрый, идеально для хранения текущего фильтра, сортировки и состояния тулбара).
Навигация: React Navigation (Drawer для бокового меню, Stack для модалок записей).
Хранение настроек: expo-secure-store (для PIN-кода) и AsyncStorage (для выбранной темы и режима сортировки).
6. План публикации (Google Play & App Store)
Google Play (Android):
Аккаунт разработчика ($25 единоразово).
Сборка .aab (Android App Bundle) через EAS Build (Expo Application Services).
Заполнение страницы в консоли (скриншоты, описание, политика конфиденциальности).
App Store (iOS):
Аккаунт разработчика Apple ($99/год).
Сборка через EAS Build.
Важно: Apple строго относится к приложениям с пользовательским контентом. Поскольку это личный дневник, в описании нужно четко указать, что данные хранятся локально на устройстве и не передаются на серверы (это упростит прохождение модерации).
